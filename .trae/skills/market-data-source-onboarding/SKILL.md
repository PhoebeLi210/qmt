# 行情数据源接入规范（chaogu）

新增任何外部行情/财务数据源（akshare 新接口、商业 API、爬虫源）时按本流程执行。核心原则：**先算账再写码、机房实测、只做有保护的兜底、密钥永不入库、测试不打真实接口**。

## 0. 触发场景

- 现有主数据源被封/不稳定（表现为推荐字段全空、定时任务连续失败）
- 用户提供新 API key 要求接入
- 需要现有源不具备的数据品类（资金流、盘口、财务）

## 1. 评估阶段（写代码前必须回答）

**额度账**——按程序真实调用量估算，不要只看接口能调通：

- 全市场扫描约 5400 只，每只详情至少 3 个请求（个股资料+日K+估值）≈ 1.6 万请求/天
- 盘中监控每 2 分钟一轮全市场快照（单请求批量拉全市场的源才有资格做主源）
- 自选分析是小名单（通常几十只），免费窄额度源只能放这里
- 结论模板：免费版 10 次/分级别的源，全市场 K 线需要 9 小时以上 → 只能当第三兜底，预算封顶

**字段账**——对照评分依赖逐字段确认，缺字段必须显式降级，不许造假：

- 必需项：日K OHLCV（≥20 根）、行业、PE/PB、主力资金流（fund_factor 乘数）、历史换手率（筹码因子依赖换手率序列）
- 例：AlphaFeed 日K 无历史换手率 → 走该源的股票 turnover=None，筹码因子中性降级，形态/量价/资金评分不受影响

**口径账**：复权方式（统一前复权）、代码格式、涨跌幅是小数还是百分数、日期格式。

## 2. 机房实测（本地可用 ≠ 线上可用）

已知事实：机房 IP 被东财 push2/push2his/80.push2 系列域名封死（ConnectionError），但 datacenter-web.eastmoney.com、新浪、乐咕乐股、baostock 可达。任何新源必须在**服务器**上验证，不在本机拍板。

- 探针脚本放 `.deploy/probe_*.py`，scp 到服务器 /tmp，`sed -i 's/\r$//'` 去 \r，用 `runuser -u chaogu -- venv/bin/python` 执行
- 复杂脚本禁止 ssh 内联 `python -c`（PowerShell 引号必坏）；远程进程用 `setsid ... > /tmp/x.log 2>&1 < /dev/null &` 后台跑
- 带 key 的探针：key 只经 `env KEY=xxx` 进程级注入，脚本里只读环境变量；验证完删除探针
- 实测内容：连通性、耗时（含登录耗时）、字段清单、关键股票核对（300750 创业板/605168/688981 科创板是覆盖度试金石）、快速打超额度观察限流报错格式（Retry-after 是毫秒还是秒要解析确认）
- 坑记录：baostock 首次登录要 2-3 分钟，采集器全局 socket 超时 30s 会导致"网络接收错误"，登录期间必须临时 `socket.setdefaulttimeout(None)`

## 3. 接入模式

- 新源默认进**回退链末尾**，不替换主源；例：K线 东财hist→新浪daily→AlphaFeed；报价 东财快照→新浪批量→AlphaFeed；行业 东财→baostock→申万→新浪
- 批量优先：能一次请求拿全市场的源（如 baostock `query_stock_industry` 一次 5222 只 4.5 秒）远优于逐板块/逐股爬取（131 个网页 × 节流 = 易触发反爬）
- 适配代码独立成模块（参考 `alphafeed_source.py`），业务代码只在失败分支 import 调用，禁止让新源成为硬依赖
- SDK 未安装/无 key 时静默禁用，日志一行 info 即可，不得影响启动
- symbol 转换集中处理：内部 sh.600000/sz.000001，北交所 bj.* 多数商业源不支持，直接返回 None 跳过

## 4. 密钥安全

- 只放 `/opt/chaogu/chaogu.env`（systemd EnvironmentFile，chmod 600，属主 chaogu），代码只引用环境变量名
- 不入 git、不入日志、不写进探针文件、不出现在异常信息回显中
- 用户在对话里发过明文 key 时，交付提醒其去服务商后台轮换
- 依赖写进 `requirements.txt` 并标注"可选；无 key 时自动禁用"

## 5. 限频 / 熔断 / 预算（兜底源的强制三件套）

参考 `alphafeed_source.py` 实现：

1. **端点独立限频**：按额度算最小调用间隔（10次/分 → 6.2s），sleep 在锁外避免阻塞另一端点
2. **熔断分类**：401/403/invalid key → 本进程永久禁用；RateLimit/429 → 按报错中 Retry-after 冷却；普通网络错 → 短冷却 30s
3. **进程预算**：兜底源设调用次数上限（K线默认 60，env `CHAOGU_AF_KLINE_BUDGET` 可调），防止全市场扫描主源大面积故障时在窄额度源上耗数小时；预算用尽直接返回空
4. 提供 `status()` 返回 ready/no-key/cooling/disabled 供诊断，`reset_for_tests()` 与注入式假客户端供测试

## 6. 缓存策略

- 变化慢的数据（行业归属）按日缓存 `cache/xxx.json`（含 date/src/map），同时写带日期历史副本，全部源失败时沿用最近缓存并 log warning——过期但合理的数据远好于空值
- 行情类短缓存沿用 monitor 既有秒级缓存；K线失败短缓存 10 分钟
- 换源验证时先删当日缓存，否则旧缓存会让新源不生效

## 7. 测试与交付

- 单测用**注入假客户端**（DataFrame 构造返回），覆盖：符号转换、字段归一化（pct 小数转百分数、无效价格过滤）、分批大小、限频冷却、鉴权永久禁用、预算耗尽、无 key 静默；以及业务链路测试（mock 掉所有主源后确认兜底被调用、主源成功时兜底零调用）
- 测试绝不打真实接口（额度会被测试吃光且不可重复）
- 本地：`$env:PYTHONPATH="$PWD\.deps"; py -3 -m unittest <新测试> <既有全部测试>`，服务器部署后同样跑一遍
- 部署：scp → `install -o chaogu -g chaogu -m 644` 到 /opt/chaogu → `systemctl restart chaogu` → 确认 active → 用 env 注入 key 跑一次真实链路探针（gunicorn 是 127.0.0.1:18001）→ 删除探针
- 杀远程后台进程用 `pkill -f '[n]ame.py'`（[] 防止匹配到自己的 ssh shell 导致连接被断）
- 更新项目记忆 project_memory.md：数据源顺序、额度、坑、降级行为

## 8. 反模式（本项目已踩过的坑）

- 在本机验证通过就上线（机房 IP 封禁会让行业全变"-"）
- 把免费窄额度源接进全市场主链路（扫描时长按小时计）
- key 硬编码进源码或探针
- 爬 131 个网页做本来一次批量查询能拿到的数据（反爬封锁后全挂）
- 新源缺字段时填 0 或默认值（污染评分；正确做法是 None + 因子降级）
- 定时任务只判断周一到周五——法定假日必须过 `webapp.monitor.is_trading_day()`
- 凭直觉猜 SDK 方法签名——先 dir() 枚举资源对象（klines/quotes 是对象不是函数，方法是 .get），按报错收敛参数
